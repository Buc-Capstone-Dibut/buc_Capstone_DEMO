# 워크스페이스 콘솔 재개

## Why

종료한 워크스페이스의 데이터는 남아 있지만 소유자가 다시 진행 중으로 바꿀 수 있는 진입점이 없다.

## Outcome

소유자는 워크스페이스 상세 화면의 브라우저 Console에서 `await workspaceControl.reopen()`을 실행해 현재 워크스페이스를 재개한다. 성공하면 화면을 새로고침해 읽기 전용 상태를 해제하고 실시간 연결을 다시 시작한다.

## Boundaries

- `POST /api/workspaces/[id]/reopen`은 서버에서 검증한 로그인 사용자와 해당 워크스페이스의 `owner` 권한을 확인한다. 다른 구성원·비구성원·비로그인은 변경할 수 없다.
- `COMPLETED`를 `IN_PROGRESS`로 바꾸고 `completed_at`만 비운다. 문서·보드·채팅·멤버·결과 메타데이터와 기존 커리어 후보·알림·평판은 유지한다.
- 이미 진행 중인 공간에 대한 재실행은 성공 응답을 반환하되 DB를 갱신하지 않는다. 삭제한 공간을 복구하거나 권한을 부여하지 않는다.
- 콘솔 명령은 소유자의 상세 화면에서만 등록하고 페이지를 벗어나면 제거한다. 중복 실행은 하나의 요청으로 처리하고 실패 시 새로고침하지 않는다.
- 기능 검증을 위해 실제 사용 중인 워크스페이스 상태를 임의로 변경하지 않는다.

## Done when

- 소유자는 종료한 공간을 재개할 수 있고, 비소유자의 직접 API 호출도 거부된다.
- 상태 변경은 종료 상태와 소유권을 조건으로 수행하며, 그 외 데이터는 갱신하지 않는다.
- 진행 중인 공간 재요청, 잘못된 ID, 삭제된 공간, 동시 상태·권한 변경과 서버 오류를 처리한다.
- 콘솔 명령의 등록·해제, 중복 요청, 성공 후 새로고침과 실패 시 재시도를 검증한다.
