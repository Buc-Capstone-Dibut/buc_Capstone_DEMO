# 워크스페이스 보드

## Why

기존 작업 화면은 워크스페이스의 모든 태스크를 하나의 칸반에 모아 보여줘, 서로 다른 업무 흐름을 독립적으로 관리하기 어렵고 “목표 태그”가 사실상 부모 구조처럼 오해됐다. 보드를 태스크의 수평적인 묶음으로 두되, 상태·담당자·우선순위·태그는 보드의 상위 개념으로 확장하지 않고 같은 작업을 보는 기준으로 유지한다.

## Outcome

- 사용자는 작업 메뉴에서 보드 목록을 먼저 보고 원하는 보드로 들어간다.
- 사용자는 보드를 만들고 이름·설명을 수정하며, 기본 보드를 제외한 보드를 보관하거나 복원한다.
- 각 태스크는 반드시 하나의 보드에 속하고 다른 활성 보드로 이동할 수 있다.
- 같은 보드의 작업을 목록과 칸반으로 전환하고 상태·담당자·우선순위·태그 기준으로 그룹화한다.
- 검색과 필터는 목록과 칸반에 동일하게 적용된다.
- 작업에는 날짜만 사용하는 시작일과 종료일을 각각 지정한다.

## Boundaries

- 내비게이션 이름은 “작업”, 데이터 단위 이름은 “보드”로 한다.
- 보드는 목표·에픽·스프린트 같은 상하 구조가 아니라 서로 독립적인 수평 분류다.
- 상태·우선순위·태그·멤버는 이번 단계에서 워크스페이스 공용 설정을 유지한다.
- 보드는 영구 삭제하지 않고 보관·복원한다. 기본 보드는 보관할 수 없다.
- 태그는 그룹 기준이자 메타데이터이며 보드나 목표의 대체 식별자로 사용하지 않는다.
- 기존 태스크는 “기본 보드”로 이관하고 기존 마감일은 한국 시간 기준의 종료일로 보존한다.

## Done when

- 작업 메뉴 진입 시 보드별 작업 수, 완료율, 담당자 수, 기간을 확인하고 한 번의 동작으로 상세에 들어갈 수 있다.
- 기존 태스크가 누락되지 않고 모두 기본 보드에 속한다.
- 목록과 칸반에서 네 가지 그룹 기준과 공통 검색·필터가 실제 표시 결과를 바꾼다.
- 작업의 시작일·종료일을 저장하고 다시 열어도 같은 날짜가 표시되며 시작일이 종료일보다 늦은 값은 저장되지 않는다.
- 존재하지 않는 태그 ID를 작업에 저장할 수 없고, 태그 삭제 시 작업의 참조도 함께 제거된다.
- 보관된 보드는 일반 목록과 작업 이동 대상에서 제외되고 보관함에서 복원할 수 있다.

## Next

아래 항목은 현재 보드 구조를 안정화한 뒤 별도 작업으로 진행한다.

- 보드 목록을 단순 표를 넘어 최근 활동, 일정 위험, 담당 현황을 빠르게 파악할 수 있는 보드 허브 레이아웃으로 고도화한다.
- 같은 태스크 데이터를 캘린더와 타임라인 레이아웃에서도 조회할 수 있게 한다.
- 캘린더에서 태스크를 드래그하거나 기간 가장자리를 조절해 시작일·종료일을 빠르게 변경하고, 충돌·지연 상태를 즉시 확인할 수 있게 한다.
- 보드별 기본 레이아웃과 사용자가 마지막으로 선택한 레이아웃을 저장하는 방식을 설계한다.
