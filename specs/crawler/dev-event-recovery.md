# 대외활동 데이터 복구

## Why

같은 원문이 서로 다른 저장 키로 중복 저장되고, 등록 시각이 같은 배치의 최신순 정렬이 불안정하다. 상세 수집 횟수 제한 때문에 목록만 저장된 활동이 많고 자동 실행 설정도 누락되어 있다.

## Outcome

- 출처와 공식 링크를 고유 키로 통일하고 가장 오래된 ID에 상세 데이터를 합친다.
- 합쳐진 ID는 별칭으로 보존하고 연결된 팀 모집은 유지한다.
- README 연도·월과 접수/행사 날짜를 파싱하고 최신순은 시작일, 종료일, 고정 ID 순으로 정렬한다.
- 비어 있는 상세 정보를 이어서 수집하고 성공 결과를 즉시 저장한다. 재실행 시 기존 요약을 보존한다.
- 자동 수집의 기본 제한을 없애고 실행에 필요한 설정을 명확하게 검증한다.

## Boundaries

- DB 정리는 백업과 사전 계획 확인 후 하나의 트랜잭션으로 실행한다. 알 수 없는 FK가 있으면 중단한다.
- 별칭 테이블은 기존 공개 행사 ID의 연결만 제공한다. 쓰기는 서비스 권한으로만 수행한다.
- 기존 요약을 실패 결과로 덮어쓰거나 원문에 없는 정보를 만들어 채우지 않는다.
- GitHub Actions Secrets 등록은 비밀값의 외부 등록 승인을 받은 후 진행한다.

## Done when

- 중복 링크가 없고 기존 ID로 상세 페이지에 접근할 수 있다.
- 날짜·안정 정렬·중복 병합·제한 및 재시도·기존 내용 보존을 검증한다.
- 누락된 상세 수집을 실행하고 수집 실패가 남으면 원인과 대상을 확인한다.
